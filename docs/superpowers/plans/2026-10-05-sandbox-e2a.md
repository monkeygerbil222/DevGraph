## Why this slice is tests-first

E2b is the first code that launches a container around repository-supplied script text. The container is *the* boundary (§2), so the attack suite is the acceptance bar for E2b and must be reviewable without the runner clouding it. Writing the tests against a frozen interface does three things: it fixes the runner's public surface now, so E2b is a fill-in-the-blanks exercise the diff can be read against; it lets a reviewer see every attack the runner is claimed to stop, in one PR, with no implementation to hide behind; and `xfail(strict=True)` makes the gate self-policing — E2b cannot quietly leave a test unimplemented (it would still xfail) nor let one pass by accident against a half-built runner (an unexpected pass is a failure), so the E2b diff must strike each marker and name exactly the tests it claims.

## The review that produced this revision

A thorough review returned **"Needs revision"** with one overriding finding: as first written, several tests could pass against an *unsafe* runner, because their probes ran under the in-container Python allowlist shim (which would stop the behaviour even with no container), because absence tests never proved their probe ran, and because the fault surface (`RunConfig`) was wide enough to let production code diverge the container. This revision closes all of that. The spine of the fix:

1. **Container-property probes run below the shim.** Every test that claims the *container* stops a behaviour drives its probe through the same below-the-shim probe route as the raw-syscall probes, with the full standard library available, so only the container — not the allowlist — can stop it (§"The probe route").
2. **Every probe proves it ran, and every refusal has an acceptance twin.** Absence tests emit an explicit result record and assert it is present; refusal/divergence tests pair with a twin that the unmutated baseline is accepted (§"The probe route").
3. **The fault surface is fenced.** `RunConfig` keeps only timing fields that may only be lowered; all fault and substitution knobs move to a private `_TestFaults` object that `run_provider` refuses unless a testing switch is on, which only the adversarial conftest flips (§"The runner interface").

## Global Constraints

- **E2a writes no runner.** The only new non-test code is the **stub interface** (Task 1): modules under `devgraph/sandbox/` whose public functions and dataclasses have their final signatures but whose bodies are `raise NotImplementedError("E2b")`, plus `devgraph/sandbox/_testing.py` (the fault type and the testing switch) and the §6 runtime constants added to `limits.py`. No task in E2a creates a container, opens a socket, writes a seccomp profile that is loaded, or shells out to `podman` (the one exception is the **pin-settling inspection** of Task 5, which `podman pull`/`inspect`/`save` but never *runs* a container, and is performed when E2a is built, not during planning). Every task says "Executes repository code: no" and "Launches a container: no".
- **The stub is the contract.** Every `sandbox`-marked test drives the real entry point (`runner.run_provider`, or a pure helper such as `invocation.assert_inspect`), never a test-local reimplementation. Because the stub raises `NotImplementedError` as its first statement, a test that would otherwise create a divergent container, flood stdout or probe a syscall never reaches any of that in E2a. All divergence, shortening and substitution a test needs is expressed through `RunConfig` (timing only) and the private `_TestFaults` object, and passed *into* the stub, so the container-creating code is the single thing E2b implements and E2a never runs.
- **The xfail form (§10.1, applied).** Every container test is `@pytest.mark.xfail(strict=True, raises=NotImplementedError, reason="runner lands in E2b")` **and** `@pytest.mark.sandbox`. Naming `raises=NotImplementedError` means a `sandbox` test that reaches any *other* exception in E2a is a real failure, not a silent xfail — so a probe mis-wired to pass under the shim, or a conftest fault leak, surfaces now. The `sandbox` marker is registered in `pyproject.toml` (`[tool.pytest.ini_options] markers`).
- **The require-sandbox gate is a session hook, not a fixture (§10.1, applied).** `DEVGRAPH_TEST_REQUIRE_SANDBOX` is read in **one place**: a session-level hook in `tests/conftest.py` (`pytest_sessionstart`) that, when the variable is set and rootless Podman ≥ 5.0 is absent or rootful/remote, calls `pytest.exit(..., returncode=<non-zero>)` so the whole session fails. The decision is a small importable helper, `require_sandbox_or_exit(probe_result, *, exit=pytest.exit)`, so its own unit test drives it directly. It is **never** a per-test fixture: a fixture that skipped or xfailed would be silently swallowed by the `xfail` marker and the gate would not bind.
- **No `skipif` inside sandbox tests (§10.1, applied).** Local absence of Podman is handled by **collection-time deselection** (`pytest_collection_modifyitems` deselects `sandbox` tests when the session-scoped probe reports no rootless Podman ≥ 5.0), not `skipif`. Per-architecture cases use **architecture deselection** (the `[aarch64]` parameter is deselected off an aarch64 host). Host-dependent expectations (AppArmor on/off, SELinux on/off) are **explicit per-host branches inside the test body**: the test reads the host's state and asserts the matching expected value (e.g. `AppArmorProfile` empty when AppArmor is off, matching the `containers-default-` prefix and never `unconfined` when on). No `skipif`, no bare `pytest.skip` in any test body.
- **xfail semantics are the gate.** In E2a a `sandbox` test that runs hits `NotImplementedError` → xfailed (expected). E2b removes the `xfail` marker as it implements each test; a test left marked but passing fails the strict check, forcing E2b's diff to be honest. No test is `xfail(strict=False)`.
- **No sandbox decision from `Settings`, `.env` or the environment (§5.1),** unchanged from E1: `<home>` is `pwd.getpwuid(os.getuid()).pw_dir`; the lock, trust store and fixed registry sit under it; tests reach that home through the `paths.sandbox_home` attribute the autouse `_isolate_sandbox_home` fixture patches. **The podman process's `HOME` is separate** (see "The HOME conflict").
- **Limits are code constants (§6, Q9).** Tests assert against `devgraph.sandbox.limits`; they never hard-code a duplicate value. The §6 **runtime constants** (per-file deadline, start-up deadline, per-run wall formula and ceiling, stdin write deadline, CPU budget, memory, pids, record/byte caps, stderr keep, lock wait, conmon slack) are added to `limits.py` in Task 1 (item 13). Where a test must shorten a wall it passes a `RunConfig` override; the constant is never mutated and **no override widens a security limit** — `RunConfig` has no field for memory, pids, caps, network, userns, seccomp or read-only rootfs, and a timing override may only *lower* the constant (enforced in `RunConfig.__post_init__`).
- **The fault fence (item 3).** Fault injection and substitution never touch `RunConfig`. They live in a private `_TestFaults` object (`devgraph/sandbox/_testing.py`), which `run_provider` accepts only when `devgraph.sandbox._testing.enabled()` is true; the adversarial `conftest.py` is the **only** place that calls `enable()` (in a fixture that `disable()`s on teardown). A static test (`test_no_production_fault_surface`) asserts that no module under `devgraph/` other than `runner.py` and `_testing.py` references `_TestFaults`, and that no module under `devgraph/` passes `config=` to `run_provider` (production always uses the defaults).
- **Fixtures carry no payload code (§ this plan).** Each malicious script or probe body lives under `tests/sandbox/adversarial/` and is described in this plan in neutral, defensive terms only. The implementer writes the body. No attack payload text appears in this document.
- **Bounded fixtures only (item 10).** Every resource fixture bounds itself and names no real target (§"Bounded fixtures").
- **Reasons quote no value (§8).** Where a test asserts a refusal names a field (inspect row, report field, frame rule), it asserts the *field name and rule* from a fixed vocabulary, never that any script value, file byte, record value or report value is echoed. The grep-based `test_reasons_quote_no_values` is **replaced** by unique-sentinel tests (§"Sentinels, not grep").
- **Error codes (§8).** Assertions use the spec's codes: `disabled`, `pending`, `awaiting_approval`, `sandbox_unavailable`, `input_unavailable`, `static_reject`, `input_cap`, `input_decode`, `busy`, `timeout`, `memory`, `output_cap`, `protocol`, `schema_violation`, `crash`, `aborted`. E2a pins the set as `RUN_ERROR_CODES` in `limits.py` (item 13) so a test asserts completeness.
- **Scope, corrected (item 13).** E2a adds stub files under `devgraph/sandbox/`, the `_testing.py` fault module, the §6 runtime constants and `RUN_ERROR_CODES` in `limits.py`, the `sandbox` marker in `pyproject.toml`, and the session hook in `tests/conftest.py`. It changes no E1 *logic*. The earlier "no change to E1 modules" line is amended: adding the runtime constants and `RUN_ERROR_CODES` to the existing `limits.py`, and the session hook to the existing `tests/conftest.py`, are the sanctioned E1-file edits.
- TDD per task: write the tests (which xfail, or pass for the few that exercise only the stub surface and the harness), confirm the whole suite is green under `uv run pytest -q` with every `sandbox` test xfailed or deselected, then commit. No implementation step beyond the Task 1 stubs and constants.
- Commit messages are plain imperative, no `Co-Authored-By` trailer and no AI attribution. Never commit `uv.lock`, real names or personal paths. Fixtures and the plan use fictional repository and user names.

## Review Focus

Reviewers should spend their time here. This suite *is* the review of E2b's security claims, so the questions are "is every boundary tested?" and "can a test pass without the boundary holding?".

1. **No test passes against an unsafe runner.** Container-property probes run **below the shim** with the full stdlib (§"The probe route"); absence tests prove their probe ran (an explicit result record, asserted present); every refusal/divergence test has an acceptance twin; `escape_*` tests assert the escape reached its attempt step; a **host canary** token in a `tmp_path` file outside the repo is asserted absent from every output, record, stderr and log.
2. **The gate cannot be gamed.** Every container test is `xfail(strict=True, raises=NotImplementedError)` *and* `sandbox`; none reaches E2a execution. No `xfail(strict=False)`, no `skipif` or bare `pytest.skip` in a test body, no test asserting on a test-local fake instead of the stub. `DEVGRAPH_TEST_REQUIRE_SANDBOX` is read only in the `conftest.py` session hook.
3. **The fault surface is fenced.** `RunConfig` is timing-only and lower-only; faults are in `_TestFaults` behind `_testing.enable()`; `test_no_production_fault_surface` holds the line. Confirm no test file imports `subprocess`/`socket`/`ctypes` to *perform* an attack in-process (fixtures and probe bodies may, to run later inside the container; tests may not).
4. **Coverage against §4 and §6 is complete.** Each inspect row (§4.3 table), each report check (§4.4), each limit (§6 table), each denied-syscall family (§4.3 list), each readiness condition (§4.3), each escape row (§4.1) and each frame rule (§4.4) has at least one test, enumerated by parametrisation so a missing row is a missing parameter visible in the diff. Pure row tests on recorded JSON are kept **separate** from live-injection tests.
5. **The frame and record corpora are strict and allocation-safe.** `test_hostile_frames` and `test_record_validator_corpus` pin one error code per entry (`protocol` for a frame or undecodable input; `schema_violation` for a decode or validate failure), reject an oversize declared length *before allocation*, and never crash or hang.
6. **Every Unverified item is assigned.** The §"Settling the spec's Unverified items" section names, for each Unverified statement, the test that settles it or the exact inspection E2a runs and records.
7. **The CI workflow matches the gate (Q15).** `sandbox-linux` and the **required** `sandbox-linux-arm64` run every `sandbox` test with `DEVGRAPH_TEST_REQUIRE_SANDBOX=1` on rootless Podman ≥ 5; the unit job runs `-m "not sandbox"` on ubuntu and macOS. Workflow hygiene (SHA-pinned actions, least privilege, stable job ids) per §"CI".

## The runner interface the tests target

E2a creates these modules under `devgraph/sandbox/` as **stubs** (final signatures; bodies `raise NotImplementedError("E2b")`). E2b implements them and removes the `xfail` markers. Signatures are fixed here so the two slices meet exactly, and are pinned by `test_runner_interface_signatures` (item 8: `inspect.signature` on each public callable), which **replaces** the old "call each stub, assert it raises" test.

### `devgraph/sandbox/runner.py`

- `@runtime_checkable class ProviderSnapshot(Protocol)` — **frozen minimal shape now** (item 5): `provider_name: str`, `declaration: Mapping[str, Any]`, `script_text: str`, and `iter_inputs() -> Iterator[tuple[str, str]]` (repo-relative POSIX path, UTF-8 text). E2b's snapshot and the tests' duck-typed fakes both satisfy it; `test_provider_snapshot_protocol` checks a minimal fake is an instance.
- `@dataclass(frozen=True) class RunConfig` — **timing only** (item 3). Fields, each `float | None` defaulting to `None` meaning "use the `limits.py` constant": `start_deadline_s`, `per_file_deadline_s`, `run_ceiling_s`, `stdin_write_deadline_s`, `lock_wait_s`. `__post_init__` raises `ValueError` if any set value **exceeds** its corresponding constant (a timing override may only *lower*). There is **no** `inject_env`, `deaths`, `inject_create_flags`, `podman_home`, `entrypoint_args` or `bootstrap_override`. `test_run_config_lower_only` asserts a raised value is refused and a lowered one accepted.
- `@dataclass(frozen=True) class FileResult` (item 5) — `path: str`, `outcome: str` (`"ok"` or an error code), `nodes: int`, `edges: int`, `records: tuple[Mapping[str, Any], ...] | None` (the validated records, present on a `--dry-run`), `probe_output: Mapping[str, Any] | None` (the raw probe output, present in probe mode; `None` otherwise). The two observation channels are distinct so a probe test reads `probe_output` and a dry-run test reads `records`.
- `@dataclass(frozen=True) class RunResult` — `outcome: str`, `files: tuple[FileResult, ...]`, `error_counts: Mapping[str, int]`, `duration_s: float`, `container_launched: bool`.
- `@dataclass(frozen=True) class SchemaViolation` — `field: str`, `record_index: int`, `rule: str`; **no value** (§8). The marker object a decode/validate failure yields.
- `class SandboxUnavailable(Exception)` with `.field: str | None` (from `FIELD_NAMES`, never a value) and `.code = "sandbox_unavailable"`. **Decision (item 5): `sandbox_unavailable` raises**; it is not a return value.
- `class ProtocolError(Exception)` with `.code = "protocol"`.
- `FIELD_NAMES: frozenset[str]` — the fixed `field` vocabulary (item 5): exactly the §4.3 inspect-table row names and the §4.4 report field names. `SandboxUnavailable.field`, when set, is in this set; `test_field_vocabulary` pins it to the §4.3/§4.4 tables so a typo'd field name is caught.
- `run_provider(snapshot: ProviderSnapshot, repo_id: str, canon: str, *, config: RunConfig = RunConfig(), _faults: "_TestFaults | None" = None) -> RunResult` — the integration entry every `sandbox`-marked test calls. `_faults` is refused with a `RuntimeError` unless `devgraph.sandbox._testing.enabled()`.
- `validate_records(records: Sequence[Mapping[str, Any]], declaration: Mapping[str, Any]) -> list[Mapping[str, Any]] | SchemaViolation` — the pure §3.3 record validator (item 5), driven by the record-validator corpus independently of any container.
- `compare_runs(first: RunResult, second: RunResult) -> tuple[tuple[str, str], ...]` — the pure `--twice` comparator (item 5): the (path, differing-aspect) pairs, empty when the two runs agree. The determinism test drives it on a recorded pair.
- `RUN_ERROR_CODES: frozenset[str]` — **imported from `limits.py`** (item 13), re-exported here only as a name; `test_run_error_codes_complete` asserts it equals the §8 set.
- `sweep_leftover_containers(*, max_wall_s: float, now: float | None = None) -> int` — the start-up sweep (§4.4).

### `devgraph/sandbox/_testing.py` (private; the fault fence)

- `enable() -> None`, `disable() -> None`, `enabled() -> bool` — a process-local switch (not an env var, not `Settings`).
- `@dataclass(frozen=True) class _TestFaults` — every fault and substitution knob, one field each:
  - `divergence: DivergenceCase | None` — an **enumerated** divergence (item 3), one member per inspect or report row the tests need (e.g. `NETWORK_MODE`, `USERNS_MODE`, `SECCOMP_PROFILE`, `CAP_DROP`, `NO_NEW_PRIVS`, `READONLY_ROOTFS`, `MEMORY`, `PIDS_LIMIT`, `USER`, `LOG_DRIVER`, `ULIMITS`, `ENV_VIA_CONTAINERS_CONF`, `MOUNT_VIA_MOUNTS_CONF`, `REPORT_UID`, `REPORT_CAP`, `REPORT_SECCOMP`, `REPORT_ENV`, `REPORT_HOME`, `REPORT_HOSTNAME`, `REPORT_RUN_SECRETS`, `REPORT_MOUNT_TYPE`, `REPORT_RO_AS_RW`). This replaces the free-form `inject_create_flags` and the `podman_home` knob for row divergence; `test_divergence_case_covers_rows` asserts the enum has one member per inspect/report row.
  - `bootstrap: str | None` — the **single merged** entrypoint-body substitution (item 4), replacing `entrypoint_args` and `bootstrap_override`. It substitutes only the `-c <body>` string; `--entrypoint` and the interpreter path are **never** overridable. A probe `bootstrap` is the real bootstrap's **report phase** followed by the probe body, so `check_report` still runs before the probe executes.
  - `podman_home: Path | None` — a temporary `HOME` for the podman process, for the `mounts.conf`/`containers.conf` divergence cases only (the `.config/containers/{containers,mounts}.conf` a test populates). Distinct from the sandbox home (§"The HOME conflict").
  - `stock_seccomp: bool` — route this run through Podman's **stock** seccomp profile instead of ours, the legal control for the seccomp probes (item 7): under the stock profile a denied family *succeeds*, proving the test's premise.

### `devgraph/sandbox/invocation.py`

- `podman_env() -> dict[str, str]` — the constructed environment (§4.3): `PATH` (fixed), `HOME` (from the password database, §"The HOME conflict"), `XDG_RUNTIME_DIR`, `LANG`, nothing else.
- `build_create_argv(*, name, image_ref, entrypoint, args, timeout_s, config, faults=None) -> list[str]` — the `podman create` argv (§4.3). `--entrypoint` and the interpreter path are computed from the constants and are **never** taken from `faults`; a `faults.divergence` alters exactly one other flag.
- `IMAGE_PINS: Mapping[str, ImagePin]` keyed by architecture; `@dataclass(frozen=True) class ImagePin` — `image_id`, `manifest_list_digest`, `per_arch_digest`, `repo`, `interpreter_path`, `config_env: tuple[str, ...]`, `home`, `entrypoint: tuple[str, ...]`, `apparmor_profile: str | None`. Values recorded by the pin-settling inspection (Task 5). AppArmor is matched by the `containers-default-` **prefix** (never `unconfined`), not an exact string.
- `expected_args(*, bootstrap: str) -> tuple[str, ...]` — computes the inspect `Args` from the bootstrap actually used (item 4). Production calls it with the constant `BOOTSTRAP`; a probe test calls it with `faults.bootstrap`, so `assert_inspect` checks the Args that were really passed.
- `assert_inspect(container_inspect: dict, image_inspect: dict, *, arch: str, args: Sequence[str]) -> None` — raises `SandboxUnavailable(field=...)` on the first row of the §4.3 table that diverges; `args` is `expected_args(...)` from the runner. The pure function the inspect tests drive on recorded fixtures and E2b drives on a live create.
- `assert_image_pin(image_inspect: dict, *, arch: str) -> None` — image ID, list digest, per-arch digest, `RepoDigests` (§4.3).
- `check_readiness(info: dict) -> None` — the `podman info` readiness gate (§4.3); raises `SandboxUnavailable(field=...)`.

### `devgraph/sandbox/report.py`

- `MOUNT_ALLOWLIST: tuple[MountRule, ...]` — the §4.4 `(mount point, fs type, ro|rw)` table; its clean-host regeneration is `test_mount_allowlist_clean_host`.
- `check_report(report: dict, *, expected_env: Mapping[str, str], container_id: str, arch: str) -> None` — the in-container mount/identity/environment check (§4.4); raises `SandboxUnavailable(field=...)`, naming the field, never its value.

### `devgraph/sandbox/frames.py`

- `MAX_REPORT_FRAME` (64 KiB, for the report and `ready`), `MAX_RESULT_FRAME` (1 MiB + envelope) — the §4.4/§6 caps; `max_len` for a read always comes from these module constants (item 8), never a literal.
- `write_frame(buf, obj) -> None`; `read_frame(buf, *, max_len: int) -> bytes` — 4-byte big-endian length then body; a declared length over `max_len` raises `ProtocolError` **before allocation**.
- `decode_result(raw: bytes, *, expected_seq: int) -> list[dict] | SchemaViolation` — the strict decoder of §3.3 (item 5: a **single, consistent** return union — validated records, or one `SchemaViolation` marker; never a raw exception and never a mixed shape). `parse_constant` rejects NaN/Inf; int64 bound with a digit-count pre-check; finite floats; lone surrogates and NUL rejected; UTF-8 byte-length caps; nesting ≤ 2 below a record; wrong `seq` is `protocol` (a `ProtocolError`), decode/validate failures are `schema_violation` (a `SchemaViolation`). `test_decode_result_return_shape` pins that both branches are reachable and typed.
- `step_frames(state, frame)` / `class FrameSequence` — a **pure** session function for the frame-sequence rules (item 5): it advances a lockstep `seq`, and flags an extra, early, or out-of-order frame, or bytes before the report, as `protocol`, with no I/O. The host-side sequence tests drive it directly; E2b wires it under the I/O threads.

These stubs, `_testing.py`, and the `limits.py` additions are the **only** non-test source E2a adds. `devgraph/sandbox/__init__.py` stays re-export-free (E1 convention).

## The probe route, the two assertions, and the host canary

**The probe route (item 1).** Two kinds of behaviour the *container* is claimed to stop are proven by running the probe **below the in-container Python allowlist shim, with the full standard library**, through the same route the raw-syscall probes use (`_TestFaults.bootstrap` = report phase + probe body):

- **Raw-syscall probes** — `unshare`, `clone`/`clone3` with a `CLONE_NEW*` flag, `setns`, `io_uring_setup`, `bpf`, `ptrace`, `process_vm_readv`/`writev`, `socket`/`socketpair`, the mount family.
- **Container-property probes** — `net_connect`, `read_proxy_env`, `read_host_files`, `list_run_secrets`, `read_mountinfo`, `read_userns_maps`, `tmpfs_write`, `fork_bomb`. These were originally `derive` scripts under the allowlist, where the shim — not the container — would have stopped them, so the test would pass against an unsafe runner. They now run below the shim; only the container can stop them.

**Two assertions per boundary (item 1).**

- **Absence tests prove the probe ran.** Every "X is not reachable" probe emits an explicit result record (e.g. `{"probe": "read_host_files", "ran": true, "found": []}`) and the test asserts that record is **present** in `FileResult.probe_output` *and* that the sought thing is absent. A silent no-op cannot pass.
- **Acceptance twins.** Every refusal/divergence helper — `assert_inspect`, `check_report`, `check_readiness`, `assert_image_pin` — gets a **twin** test that the **unmutated baseline is accepted** (no raise). A helper that rejected everything would fail its twin.
- **Escape tests reach the attempt.** Each `escape_*` test asserts the escape **reached its attempt step** (the fixture records it got to the `getattr`/`.format`/`gi_frame`/`__import__`/`eval` call) and that, below the shim, it still could not read the host filesystem, open a socket or write a file — the container, not the lint, is the boundary.

**The host canary (item 1).** A session fixture writes a unique random token into a file in `tmp_path`, **outside the repository**, and the suite asserts the token appears in **no** `RunResult`, `FileResult.records`/`probe_output`, stderr capture, caplog record or on-disk log, for every probe and every run. It is the single tripwire for any path that leaks host-side state into container-visible output or logs.

## The HOME conflict

Podman's process `HOME` (used by the rootless client to find `XDG_RUNTIME_DIR` and storage) comes from the **real** password-database entry (`pwd.getpwuid(os.getuid()).pw_dir`), which `invocation.podman_env()` reads directly. That is **separate** from the sandbox home the `_isolate_sandbox_home` autouse fixture patches (`paths.sandbox_home`), which only moves the trust store, the fixed-path registry and the machine lock into `tmp_path` (item 9). The two must not be conflated: a test that needs a controlled podman `HOME` (the `mounts.conf`/`containers.conf` divergence) sets `_TestFaults.podman_home`, which the runner uses for the podman process only; it never redirects `podman_env()`'s real-pwd `HOME` for other tests, and it never touches `paths.sandbox_home`. `test_podman_home_separate_from_sandbox_home` pins that `podman_env()["HOME"]` tracks the pwd entry while the lock/trust paths track the patched sandbox home.

## Sentinels, not grep

The old `test_reasons_quote_no_values` grepped error strings. It is **replaced** (item 8) by **unique sentinels**: each refusal/divergence test plants a unique sentinel as the offending value (a script value, file byte, record value or report value), then asserts the sentinel is absent from `str(exc)`, from `exc.args`, **and** from `caplog` captured at `DEBUG`. A reason that interpolated the value would carry the sentinel and fail. This is stronger than a grep because it is per-value and covers the log, not just the message.

## Bounded fixtures

Every resource fixture bounds itself and names no real target (item 10):

- `fork_bomb` stops at about **2× the pids cap**; `mem_hog` stops at about **2× the memory cap**; `cpu_spin` and the hang fixtures finish on their own; output/stderr floods stop at a **bounded multiple of the cap**.
- **Network targets are only TEST-NET-1 (`192.0.2.1`)**, or a **host loopback listener the test owns** and afterwards asserts received **zero** connections. No DNS name, no public address.
- **Local canaries only** — the host canary (above) and fixture-local files under `tmp_path`.
- `ptrace` and `process_vm_readv`/`writev` target **self or a child only**.
- **There are no real exfiltration targets** anywhere in the suite; this is stated in the fixture `MANIFEST` header and backed by the host canary.

## The E2b test-edit rule

E2a's tests are the acceptance bar, so E2b must not quietly rewrite them (item 14). **E2b's diff to `tests/sandbox/adversarial/` is limited to marker removal (striking `xfail`) and recorded-data fills (the empty/`TODO` recorded-JSON baselines and `IMAGE_PINS` values).** Any change to an assertion, a parametrisation, a fixture body's intent, or the interface signatures is **out of that budget** and must be listed line-by-line in the E2b PR body for the user's sign-off. A short `tests/sandbox/adversarial/conftest.py` comment states the rule so the E2b reviewer can hold it.
