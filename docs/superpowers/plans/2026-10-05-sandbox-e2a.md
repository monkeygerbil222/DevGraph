## Why this slice is tests-first

E2b is the first code that launches a container around repository-supplied script text. The container is *the* boundary (§2), so the attack suite is the acceptance bar for E2b and must be reviewable without the runner clouding it. Writing the tests against a frozen interface does three things: it fixes the runner's public surface now, so E2b is a fill-in-the-blanks exercise the diff can be read against; it lets a reviewer see every attack the runner is claimed to stop, in one PR, with no implementation to hide behind; and `xfail(strict=True)` makes the gate self-policing — E2b cannot quietly leave a test unimplemented (it would still xfail) nor let one pass by accident against a half-built runner (an unexpected pass is a failure), so the E2b diff must strike each marker and name exactly the tests it claims.

## Global Constraints

- **E2a writes no runner.** The only new non-test code is the **stub interface** (Task 1): modules under `devgraph/sandbox/` whose public functions and dataclasses have their final signatures but whose bodies are `raise NotImplementedError`. No task in E2a creates a container, opens a socket, writes a seccomp profile that is loaded, or shells out to `podman`. Every task says "Executes repository code: no" and "Launches a container: no".
- **The stub is the contract.** Every `sandbox`-marked test drives the real entry point (`runner.run_provider`, or a pure helper such as `invocation.assert_inspect`), never a test-local reimplementation. Because the stub raises `NotImplementedError` as its first statement, a test that would otherwise create a divergent container, flood stdout or probe a syscall never reaches any of that in E2a. All divergence, shortening and substitution a test needs is expressed as fields on `RunConfig` (below) and passed *into* the stub, so the container-creating code is the single thing E2b implements and E2a never runs.
- **Markers (§10.1).** Every container test is `@pytest.mark.xfail(strict=True, reason="runner lands in E2b")` **and** `@pytest.mark.sandbox`. The `sandbox` marker is registered in `pyproject.toml` (`[tool.pytest.ini_options] markers`). A test is collected everywhere but:
  - **locally** `sandbox` tests *skip* when rootless Podman ≥ 5.0 is absent (a session-scoped fixture probes once with the constructed environment and caches the result);
  - **in CI** the `sandbox-linux` job sets `DEVGRAPH_TEST_REQUIRE_SANDBOX=1`, read **only** by `conftest.py` and never by DevGraph, under which a missing or rootful Podman **fails** the session instead of skipping.
  - `test_hostile_frames` and `test_hash_seed_not_fixed`'s host-side half and `test_escape_table`'s decoder half are **unit** tests (no `sandbox` marker) where §10.2 marks them so; they still carry `xfail(strict=True)`.
- **xfail semantics are the gate.** In E2a a `sandbox` test that runs hits `NotImplementedError` → xfailed (expected). E2b removes the `xfail` marker as it implements each test; a test left marked but passing would fail the strict check, forcing E2b's diff to be honest. No test is `xfail(strict=False)` and none uses `pytest.skip` to dodge an unfinished assertion.
- **No sandbox decision from `Settings`, `.env` or the environment (§5.1),** unchanged from E1: `<home>` is `pwd.getpwuid(os.getuid()).pw_dir`; the lock, trust store and fixed registry sit under it; tests reach the home through the `paths.sandbox_home` attribute the autouse fixture patches.
- **Limits are code constants (§6, Q9).** Tests assert against `devgraph.sandbox.limits`; they never hard-code a duplicate value. Where a test must shorten a wall value (the 60 s lock wait, the 300 s run ceiling, the 5 s start/stdin deadlines) it passes a `RunConfig` override; the constant itself is never mutated and no override widens a security limit (memory, pids, caps, network, userns, seccomp, read-only rootfs are **not** overridable — `RunConfig` has no field for them).
- **Fixtures carry no payload code (§ this plan).** Each malicious script lives under `tests/sandbox/adversarial/` and is described in this plan in neutral, defensive terms only. The implementer writes the body. No attack payload text appears in this document.
- **Reasons never quote a value (§8).** Where a test asserts a refusal names a field (inspect row, report field, frame rule), it asserts the *field name and rule*, never that any script value, file byte, record value or report value is echoed. A grep test (`test_reasons_quote_no_values`) backs this across the suite's error messages.
- **Error codes (§8).** Assertions use the spec's codes: `disabled`, `pending`, `awaiting_approval`, `sandbox_unavailable`, `input_unavailable`, `static_reject`, `input_cap`, `input_decode`, `busy`, `timeout`, `memory`, `output_cap`, `protocol`, `schema_violation`, `crash`, `aborted`. E2a pins the set in `limits.py` (or `runner.py`) as `RUN_ERROR_CODES` so a test can assert completeness.
- TDD: each task writes its tests (which xfail or, for the few that exercise only the stub's existence and the harness, pass), confirms the whole suite is green under `uv run pytest -q` with every `sandbox` test xfailed or skipped, then commits. There is no implementation step beyond the Task 1 stubs.
- Commit messages are plain imperative, no `Co-Authored-By` trailer and no AI attribution. Never commit `uv.lock`, real names or personal paths. The adversarial fixtures and the plan use fictional repository and user names.

## Review Focus

Reviewers should spend their time here. This suite *is* the review of E2b's security claims, so the questions are "is every boundary tested?" and "can a test pass without the boundary holding?".

1. **The gate cannot be gamed.** Every container test is `xfail(strict=True)` *and* `sandbox`. No `sandbox` test can pass in E2a (each must reach `NotImplementedError`). Grep the suite: no `xfail(strict=False)`, no bare `pytest.skip` inside a test body, no test that asserts on a test-local fake instead of the stub. `DEVGRAPH_TEST_REQUIRE_SANDBOX` is read only in `conftest.py`.
2. **Divergence is injected, never created in E2a.** Every "a deliberately divergent container is refused" test passes the divergence through `RunConfig` into the stub; nothing in a test file builds a `podman` argv, opens a socket, or writes outside `tmp_path`. Confirm no test imports `subprocess`/`socket`/`ctypes` to *perform* an attack (fixtures may, to be run later inside the container; tests may not, in-process).
3. **Coverage against §4 and §6 is complete.** Each inspect row (§4.3 table), each report check (§4.4), each limit (§6 table), each denied-syscall family (§4.3 seccomp list), each escape row (§4.1) and each frame rule (§4.4) has at least one test. A checklist in `tests/sandbox/adversarial/README.md`-equivalent is *not* created (no stray docs); instead a parametrised test enumerates the rows so a missing row is a missing parameter, visible in the diff.
4. **The frame fuzz corpus is strict and allocation-safe.** `test_hostile_frames` asserts the decoder rejects an oversize declared length *before allocating*, rejects wrong `seq`, extra/early/out-of-order frames, NaN/Inf, out-of-int64 integers (digit count checked before conversion), lone surrogates, NUL, over-deep nesting, invalid UTF-8 and oversize UTF-8 string values — each as `protocol` or `schema_violation` per §3.3/§4.4, never a crash or hang.
5. **The Unverified items are each assigned.** The "Settling the spec's Unverified items" section names, for every Unverified statement, either the test that settles it or the exact probe E2b runs and records. No Unverified item is left to "the runner will handle it".
6. **The CI workflow matches the gate (Q15).** `sandbox-linux` runs every `sandbox` test with `DEVGRAPH_TEST_REQUIRE_SANDBOX=1` on rootless Podman ≥ 5.0; the unit job runs `-m "not sandbox"` on each OS. The workflow pins the image by digest directly (not via the not-yet-existing `devgraph sandbox setup`). The plan states plainly that making `sandbox-linux` a required status check is an upstream repository setting the maintainer must apply; a file cannot.
7. **Scope.** No runner logic, no real seccomp JSON that is loaded, no graph write, no change to E1 modules beyond adding stub files and markers. Fixtures contain no payload the plan did not sanction.

## The runner interface the tests target

E2a creates these modules under `devgraph/sandbox/` as **stubs** (final signatures; bodies `raise NotImplementedError("E2b")`). E2b implements them and removes the `xfail` markers. Signatures are fixed here so the two slices meet exactly.

- `devgraph/sandbox/runner.py`
  - `@dataclass(frozen=True) class RunConfig` — the only knob bag; **test-only** fields, each defaulting to the production value so an omitted field changes nothing:
    - timing: `start_deadline_s`, `per_file_deadline_s`, `run_ceiling_s`, `stdin_write_deadline_s`, `lock_wait_s` (shorten the §6 walls for tests; may only *lower* them);
    - fault injection for the divergence tests: `inject_create_flags: tuple[str, ...]` (extra/altered `podman create` flags to force one inspect row to diverge), `inject_env: dict[str, str]` (variables planted in the *caller's* environment that must have no effect), `podman_home: Path | None` (a temporary `HOME` for the podman process whose `.config/containers/{containers,mounts}.conf` a test populates), `deaths: int` (how many container deaths to simulate, for the retry-bound test), `entrypoint_args: tuple[str, ...] | None` (replace `-c <BOOTSTRAP>` with a test probe command, for the seccomp/syscall probes), `bootstrap_override: str | None` (a bootstrap substitute, e.g. one that never reads stdin);
    - **no** field exists for memory, pids, caps, network, userns, seccomp path or read-only rootfs.
  - `@dataclass(frozen=True) class FileResult` — `path: str`, `outcome: str` (`"ok"` or an error code), `nodes: int`, `edges: int`.
  - `@dataclass(frozen=True) class RunResult` — `outcome: str`, `files: tuple[FileResult, ...]`, `error_counts: Mapping[str, int]`, `duration_s: float`, `container_launched: bool`.
  - `class SandboxUnavailable(Exception)` with `.field: str | None` (the differing inspect/report/readiness field; never its value) and `.code = "sandbox_unavailable"`.
  - `class ProtocolError(Exception)` with `.code = "protocol"`.
  - `run_provider(snapshot, repo_id: str, canon: str, *, config: RunConfig = RunConfig()) -> RunResult` — the integration entry every `sandbox`-marked test calls. `snapshot` is E1 Task 5's `ProviderSnapshot` (or, until E1 Task 3–5 land here, a minimal duck-typed fake the test builds).
  - `RUN_ERROR_CODES: frozenset[str]` — the §8 set.
  - `sweep_leftover_containers(*, max_wall_s: float, now: float | None = None) -> int` — the start-up sweep (§4.4).
- `devgraph/sandbox/invocation.py`
  - `podman_env() -> dict[str, str]` — the constructed environment (§4.3): `PATH`, `HOME` (from the password database), `XDG_RUNTIME_DIR`, `LANG`, nothing else.
  - `build_create_argv(*, name: str, image_ref: str, entrypoint: str, args: Sequence[str], timeout_s: int, config: RunConfig) -> list[str]` — the `podman create` argv (§4.3), so a unit test can assert the flag set without running it.
  - `IMAGE_PINS: Mapping[str, ImagePin]` keyed by architecture; `@dataclass(frozen=True) class ImagePin` — `image_id`, `manifest_list_digest`, `per_arch_digest`, `repo`, `interpreter_path`, `config_env: tuple[str, ...]`, `home`, `apparmor_profile: str | None`. Values recorded by the probe of §"Settling…".
  - `assert_inspect(container_inspect: dict, image_inspect: dict, *, arch: str) -> None` — raises `SandboxUnavailable(field=...)` on the first row of the §4.3 table that diverges; the pure function the inspect tests drive on recorded fixtures and E2b drives on a live create.
  - `assert_image_pin(image_inspect: dict, *, arch: str) -> None` — image ID, list digest, per-arch digest, `RepoDigests` (§4.3).
  - `check_readiness(info: dict) -> None` — the `podman info` readiness gate (§4.3); raises `SandboxUnavailable(field=...)`.
- `devgraph/sandbox/report.py`
  - `MOUNT_ALLOWLIST: tuple[MountRule, ...]` — the §4.4 `(mount point, fs type, ro|rw)` table; its clean-host regeneration is `test_mount_allowlist_clean_host`.
  - `check_report(report: dict, *, expected_env: Mapping[str, str], container_id: str, arch: str) -> None` — the in-container mount/identity/environment check (§4.4); raises `SandboxUnavailable(field=...)`, naming the field, never its value.
- `devgraph/sandbox/frames.py`
  - `MAX_REPORT_FRAME`, `MAX_RESULT_FRAME` (caps from §4.4/§6).
  - `write_frame(buf, obj) -> None`; `read_frame(buf, *, max_len: int) -> bytes` — 4-byte big-endian length then body; a declared length over `max_len` raises `ProtocolError` **before allocation**.
  - `decode_result(raw: bytes, *, expected_seq: int) -> list[dict]` — the strict decoder of §3.3 (`parse_constant` rejects NaN/Inf; int64 bound with a digit-count pre-check; finite floats; lone surrogates and NUL rejected; UTF-8 byte-length caps; nesting ≤ 2 below a record; wrong `seq` is `protocol`). Any exception maps to `ProtocolError` or a `schema_violation` marker object, never escapes raw.

These stubs are the **only** non-test source E2a adds. Nothing imports them at package import time that would pull a heavy dependency; `devgraph/sandbox/__init__.py` stays re-export-free (E1 convention).

### Task 2: Adversarial script fixtures and the fixture manifest

**Spec:** §3.3 (the `derive` shape), §4.1 (escapes), §4.3–4.4, §6; §3.5 (determinism).

Fixtures live under `tests/sandbox/adversarial/fixtures/`. Each is a `derive(ctx)`-shaped Python file (except the two bootstrap substitutes and the raw-syscall probes, noted) that attempts **one** behaviour. The implementer writes the body; this plan describes each only in neutral, defensive terms. A small `MANIFEST` (a Python dict in `tests/sandbox/adversarial/fixtures/__init__.py`) maps a logical name to its filename and the error code or outcome the suite expects, so a test can enumerate fixtures and a missing one is a missing entry.

**Fixtures (what each attempts, defensively stated):**
- `net_connect` — attempts to open an outbound network connection; the sandbox must make this impossible (no sockets).
- `read_proxy_env` — reads environment variables that would carry an HTTP/HTTPS proxy; must find none.
- `read_host_files` — attempts to read `/etc/hosts`, `/etc/resolv.conf` and `/etc/hostname`; must find them absent.
- `list_run_secrets` — lists `/run/secrets`; must find it empty or absent.
- `read_mountinfo` — reads `/proc/self/mountinfo`; used by the mount tests to confirm what is visible from inside; the host rejects an unexpected mount before this script is ever sent.
- `read_userns_maps` — reads `/proc/self/uid_map` and `/proc/self/gid_map`; the identity report, not the script, is the gate, but this exercises the in-container view.
- `tmpfs_write` — attempts to write to `/tmp`, `/dev/shm`, `/run`, `/var/tmp`; must find no writable path (unless the single permitted `--tmpfs=/tmp` exception is enabled, in which case only that path is writable, `noexec,nosuid,nodev`).
- `fork_bomb` — spawns processes toward and past the pids limit; the cgroup caps it.
- `mem_hog` — allocates beyond the memory cap; the cgroup kills the container (`memory`).
- `cpu_spin` — a pure-Python busy loop past the CPU budget; the in-container timer is hygiene, the host per-file deadline is the boundary.
- `c_level_hang` — a single long C-level call (a catastrophic regular expression or an enormous `str.join`) the in-container signal-handler timer cannot interrupt; must hit the **host** per-file deadline and fail only its own file.
- `caught_timer` — attempts to catch or disarm the in-container CPU timer, then spins; the host per-file deadline must still kill it and later files must still run.
- `stdout_flood` — emits more than the per-file record and byte caps; the frame parser rejects before allocation (`output_cap`).
- `stderr_flood` — writes a large volume to stderr; the drain keeps 8 KiB and discards the rest without blocking.
- `stdin_silent` — **a bootstrap substitute**, not a `derive` script: it never reads stdin, so the host's stdin write deadline must kill it.
- `set_order` and `set_order_sorted` — the first emits records whose order depends on `set`/`frozenset` iteration; `--dry-run --twice` must report a difference. The second wraps the same output in `sorted()`; `--twice` must report none. (Determinism, §3.5.)
- `escape_*` — one small fixture per §4.1 escape row (subclasses chain, run-time-built `getattr` of `__globals__`, a `.format` `__globals__` reach, a generator `gi_frame` chain, `__import__`/`import socket`, `exec`/`eval`/`while 1`/recursion, full-width `eval`). Each attempts the escape; the assertion is that even the escapes the static lint *misses* cannot read the host filesystem, open a socket or write a file, because the container — not the lint — is the boundary.
- `trivial` — a minimal valid `derive` returning one record; the baseline for "CPython starts under the profile and a `derive` completes".

**Raw-syscall probes** (not `derive` scripts, not under the import allowlist): a single parametrised probe command string per denied syscall family (`unshare`, `clone`/`clone3` with a `CLONE_NEW*` flag, `setns`, `io_uring_setup`, `bpf`, `ptrace`, `process_vm_readv`/`writev`, `socket`/`socketpair`, the mount family). These are sent via `RunConfig.entrypoint_args`/`bootstrap_override`, i.e. they run as the container's command, *below* the shim's allowlist, because the seccomp profile — not the allowlist — is what the test proves. The probe uses only the pinned interpreter's own standard library (`ctypes`) to issue the raw syscall and reports the resulting errno.

**Tests**, written first:
- `test_fixture_manifest_complete` — every logical name in `MANIFEST` resolves to a file on disk, and every file on disk is in `MANIFEST` (no orphan fixtures). (Passes in E2a.)
- `test_fixtures_are_wellformed` — each `derive` fixture parses as Python and defines a top-level `derive(ctx)` (parsed as data with `ast`, never executed). (Passes in E2a; this is the one place fixture text is read, and it is read, not run.)

**Steps:**
- [ ] Write the manifest tests.
- [ ] Add the fixtures (bodies by the implementer per the neutral descriptions) and the `MANIFEST`.
- [ ] `uv run pytest -q tests/sandbox/adversarial`.
