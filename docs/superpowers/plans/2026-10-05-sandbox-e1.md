## Global Constraints

- **Nothing executes repository code.** The only subprocesses E1 starts are the hardened `git ls-files` (§3.2) and the static-scan worker, which is DevGraph's own code, run under `python -I -S`, that parses untrusted text (§4.2). Nothing imports, `exec`s, `compile`s or tokenizes a provider script in the DevGraph process. Every task says "Executes repository code: no".
- **No sandbox decision comes from `Settings`, `.env` or the environment (§5.1).** `<home>` is `pwd.getpwuid(os.getuid()).pw_dir`, never `HOME`, `USERPROFILE` or `Path.home()`. Fixed paths:
  - trust store `<home>/.devgraph/script_trust.sqlite3`;
  - gate-1 registry `<home>/.devgraph/registry.sqlite3`, opened `mode=ro` with a short timeout;
  - machine lock `<home>/.devgraph/sandbox.lock` (E1 only names it as a constant).
- **Trust key:** `(repo_id, canonical repository path)`. The canonical path is the `Path.resolve(strict=True)` real path, NFC-normalised. A moved repository, a re-registered id, or a different checkout reusing an id inherits nothing.
- **Gates (§5.2), all fail closed.** Gate 1: the fixed-path registry has exactly one row matching both `repo_id` and the canonical path, and its `project_config_enabled` is true. It is never read through `project_switch.py`, which fails open. Gate 2: `scripts_enabled` for the key (absent means off). Gate 3: the provider's current digest is approved and active. Precondition: the schema is not pending. Any error while deciding means off and not approved: a store or registry that is missing, locked, corrupt or on the wrong schema version, an unknown or ambiguous repository, or a path that cannot be canonicalised.
- **Digest (§5.2), format version 1:**
  ```
  SHA-256( b"devgraph-script-trust\x00" || u8 1
           || field(provider name) || field(canonical JSON of the declaration set)
           || field(normalised script text, UTF-8) )
  field(x) = u64 big-endian byte length || x
  ```
  The declaration set is the full canonical entries: the `custom_providers` entry, every node type whose `source` is this provider, and every relationship whose `custom.name` is this provider, including relationship-level `custom.params`. Canonical JSON is sorted keys, no insignificant whitespace, `ensure_ascii`, lists in declared order, and `allow_nan=False`, so a non-finite param fails closed.
- **One snapshot.** The schema file and the script are each read once, through the reader. The digest, the approval display and the approval record all come from those same bytes. Nothing is re-read between check and use.
- **Normalisation reject set (§5.3), each a `static_reject`:**
  - not strict UTF-8;
  - a BOM;
  - a PEP 263 coding cookie on line 1 or 2;
  - NUL;
  - a CR not followed by LF;
  - a form feed;
  - any other C0 or C1 control except tab and LF;
  - any Unicode category Cf character, which covers U+202A–U+202E, U+2066–U+2069, U+200E/U+200F and the zero-width characters.

  CRLF becomes LF. The resulting `str` is what gets hashed, shown and stored.
- **Display (§5.3).** Every repository-sourced string printed (script text, paths, params, labels, sample names, diffs) shows control and format characters as `\x..` or `\u....` escapes. Script text additionally shows every non-ASCII character outside string literals and comments as `\u....`. CLI output of such strings never goes through Rich markup unescaped.
- **Consent (§5.4).** `approve` and `enable` require stdin **and** stdout to be a TTY. There is no `--yes`. `approve --sha256 <hex>` approves non-interactively only on an exact match with the current digest. **No DevGraph output ever prints an approve command containing a digest**: `show` prints the digest alone on its own line, and every hint names only the interactive commands.
- **Multiple digests (§5.6).** A new approval retires every previous digest for the provider. `--keep-previous` keeps them active, up to five active in total. A retired digest is never active again without a fresh approval.
- **Limits and constants (§6, Q9).** These are code constants in `devgraph/sandbox/limits.py`, with no override:

  | Constant | Value |
  |---|---|
  | script size | 64 KiB (65,536 bytes), reader, `static_reject` |
  | input per file | 1 MiB, `input_cap`, file skipped |
  | input per run | 32 MiB, `input_cap`, run refused |
  | input files per run | 5,000, `input_cap` |
  | approval sample | first 20 sorted paths |
  | growth flag | matched count above 2 × approved count |
  | active digests per provider | 5 |
  | YAML alias expansion | 10,000 nodes |
  | static-scan worker | 5 s wall, `RLIMIT_AS` 256 MiB, `RLIMIT_CPU` 5 s |

- **Secret-name denylist (§3.2).** It always applies, has no override, and is matched on the NFC-normalised, case-folded path: `.env*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*`, `.netrc`, `.npmrc`, `.pypirc`, `.git-credentials`, `*.kdbx`, `*.tfstate*`, `*credential*`, `*secret*`. Globs match on the NFC-normalised path, case-sensitively. `IGNORED_DIR_NAMES` also applies.
- **Hardened selection (§3.2).** The command is exactly `git --no-pager -C <real root path> -c core.fsmonitor=false -c core.untrackedCache=false ls-files -z --cached --sparse -t --stage` (git ≥ 2.45, checked with `git --version`; see §3.2 on lazy fetches). It runs with a constructed environment and nothing else:
  - `PATH` fixed to `/usr/bin:/bin`;
  - `HOME` set to an empty temporary directory;
  - `GIT_CONFIG_NOSYSTEM=1` and `GIT_CONFIG_GLOBAL=/dev/null`;
  - `GIT_CEILING_DIRECTORIES=<parent of root>`;
  - `GIT_NO_LAZY_FETCH=1`;
  - `GIT_PAGER=cat` and `LC_ALL=C`.

  stdout is piped. `git` is resolved once to an absolute path from the fixed `PATH`. A non-zero exit, no `git`, or no work tree means `input_unavailable`.
- **Reader (§3.2).** `devgraph/sandbox/reader.py` is the only code that reads:
  - a sandbox input;
  - a provider script, at the fixed path `.devgraph/providers/<name>.py`;
  - the schema file whose declaration feeds a digest.

  The checks run in this order:
  1. component containment with `is_relative_to`;
  2. `lstat` of every component from the root, refusing any symlink or non-directory intermediate;
  3. `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS)` from a root directory descriptor, falling back to component-wise `openat(O_NOFOLLOW | O_DIRECTORY)` then `O_NOFOLLOW | O_RDONLY` before kernel 5.6, always adding `O_NONBLOCK | O_CLOEXEC | O_NOCTTY`;
  4. `fstat`, which must be `S_ISREG` within the cap, then a read of at most cap + 1 bytes.
- **Schema reject set (§3.1).** All of these fail validation:
  - `custom_providers` or a custom source in any scope other than a repository's own schema;
  - an `inputs` list that is empty;
  - an input glob with a `..` segment, a leading `/`, a drive letter or UNC prefix, or a backslash;
  - a custom `custom.name` or `source.name` naming no declared provider;
  - a custom relationship endpoint at `Repository` or at a built-in label outside `_REPO_SCOPED_LABELS`;
  - a custom relationship type equal to a built-in type or to a type of another provider;
  - metadata named `custom_sources` or `custom_source` in any schema.
- **Static scan (§4.2).** It is hygiene, not a boundary. Any non-zero exit, timeout, signal or exception in the worker, including `RecursionError`, `MemoryError` and `SyntaxError`, is a `static_reject` and never a pass. It parses with `feature_version` equal to the image's Python minor version.
- **Platform (§4.5, Q14).** Linux only. On any other `sys.platform` value, `approve` and `enable` refuse and every provider's state is `unavailable (platform)`.
- **Dashboard (Q13).** Schema write routes refuse to create or edit entries with `source.provider: custom` or `provider: custom`. Deleting them stays allowed. There are no approve or enable routes.
- TDD: each task starts with failing tests, then the implementation, then `uv run pytest -q` for the whole suite.
- Commit messages are plain imperative, with no `Co-Authored-By` trailer and no AI attribution. Never commit `uv.lock`, real names or personal paths. Keep README.md and PROJECT_STATUS.md current in the task that changes behaviour (Task 7 does the user-facing write-up).

## Review Focus

Reviewers should spend their time here. Each item is a way E1 could quietly fail open.

1. **Fail-open paths in the gates and store.** Every `except` in `trust.py` and `gates.py` must return off or not approved. No gate may reach `get_settings()`, `project_switch`, `Path.home()` or `os.environ`. Grep the new package for those names; the only allowed use is doctor's display-only registry-mismatch explanation.
2. **The reader's race and type handling.** Nothing may be followed by name after the check, and the type and size decision must be made on the descriptor that is read. A FIFO must not block: that is why `O_NONBLOCK` is set. The fallback path must get the same coverage as the `openat2` path.
3. **The `git` invocation.** The environment must be constructed, not a filtered copy of the caller's. The `-c` overrides, `--cached`, `--no-pager` and the ceiling directory are all required. The marker-file test must cover every vector named in §10.2.
4. **The digest's encoding.** Check domain separation, the version byte, the length prefixes and the declaration set. The set must include relationship `custom.params` and must not be a projection. One snapshot must feed the digest, the display and the stored record.
5. **Consent UX and wording** (the user signs this slice off on it, §10):
   - TTY on both streams;
   - the typed confirmation;
   - `--sha256` compared in constant time and only for equality;
   - no digest ever on the same line as `approve`;
   - escaped display of every repository string.
6. **Schema compatibility.** Adding `name` to `NodeSource` and `custom` to `NODE_SOURCE_PROVIDERS` must not change filesystem behaviour. Every consumer that treated "has a source" as "is filesystem" must now check `provider == "filesystem"`. A repository with no schema file, or with today's schemas, must resolve exactly as before.
7. **Scope creep.** E1 must contain no runner, no container, no graph write, no `run` command and no podman readiness check. The alias bound applies to the schema loader only; other readers of schema text are unchanged in E1.

### Task 3: No-follow reader and hardened tracked-file selection

**Spec:** §3.2, §6 (input caps), §10.2.

**Files:**

- New:
  - `devgraph/sandbox/reader.py`;
  - `devgraph/sandbox/selection.py`;
  - `tests/sandbox/test_reader.py`;
  - `tests/sandbox/test_selection.py`.

**Interfaces:**

- `reader.py`:
  - `class InputError(Exception)` with `code` in `{"input_unavailable", "input_cap", "static_reject"}` and a one-line reason that never quotes file content.
  - `read_repo_file(root: Path, rel: str, *, cap: int, use_openat2: bool | None = None) -> bytes` follows the four steps in Global Constraints. `use_openat2=False` forces the fallback, for tests. `openat2` is called through `ctypes` as syscall 437 with an `open_how` struct. `ENOSYS` or `EPERM` falls back to the component walk. `rel` must be a relative POSIX path without `..`, `.` or empty segments.
  - `read_provider_script(root, name) -> bytes` reads `.devgraph/providers/<name>.py` with `cap=SCRIPT_MAX_BYTES`. A breach is `static_reject`. `.devgraph` and `providers` must be real directories.
  - `read_schema_file(root) -> bytes` reads `devgraph.schema.yaml` with `cap=INPUT_FILE_MAX_BYTES`.
  - A test-only `_after_check` hook runs between the `lstat` walk and the open, so the swap race can be tested.
- `selection.py`:
  - `git_binary() -> str | None` is `shutil.which("git", path=FIXED_PATH)`.
  - `tracked_files(root: Path, *, git: str | None) -> list[str]` runs the exact command with the constructed environment and a 30 s timeout. `HOME` is a `TemporaryDirectory`. Output is NUL-split, and names that are not valid UTF-8 are skipped and counted. Any failure raises `InputError("input_unavailable")`.
  - `select_inputs(root, globs, *, git) -> Selection(matched: tuple[str, ...], denied: int)`. A path is kept when:
    - `PurePosixPath(nfc).full_match(glob)` holds for some glob (Python ≥ 3.13, case-sensitive);
    - it is not `is_ignored_path`;
    - it is not denied.

    A path is denied when any NFC, case-folded **path component** matches a denylist pattern with `fnmatchcase`, so `.env` and `*secret*` are caught at any depth. `matched` is sorted. More than `INPUT_FILES_MAX` matches is `input_cap`.

**Tests**, written first, against real `git` in `tmp_path` (skipped if `git` is absent, except the no-git case):

- `test_selection_excludes_untracked_and_ignored_files`: untracked, `.gitignore`d, `IGNORED_DIR_NAMES` and every denylist pattern (including at depth, and in upper case) never match, even under `**/*`.
- `test_no_git_work_tree_is_input_unavailable`:
  - a plain directory nested inside another repository is not resolved to the outer one, because of `GIT_CEILING_DIRECTORIES`;

### Task 5: Static scan in a limited subprocess and the provider snapshot

**Spec:** §4.1–4.2, §5.2 (one snapshot), §5.3 (NFKC display), §5.5 (states), §3.2 (approval figures), §10.2.

**Files:**

- New:
  - `devgraph/sandbox/scan_worker.py`, a self-contained, standard-library-only module whose source is sent as `-c` text;
  - `devgraph/sandbox/scan.py`;
  - `devgraph/sandbox/snapshot.py`;
  - `tests/sandbox/test_scan.py`;
  - `tests/sandbox/test_snapshot.py`.

**Interfaces:**

- `scan.static_scan(text: str, *, timeout=5.0) -> ScanResult(findings: tuple[Finding, ...], non_ascii_code_spans: tuple[tuple[int, int], ...])`.
  - It runs `[sys.executable, "-I", "-S", "-c", WORKER_SOURCE]`. `WORKER_SOURCE` is read from `scan_worker.py` with `importlib.resources`. Because `-S` makes DevGraph unimportable in the worker, the worker must not import DevGraph.
  - The script goes on stdin and JSON comes back on stdout. The environment is `{"PATH": FIXED_PATH, "LC_ALL": "C.UTF-8"}`.
  - `preexec_fn` sets `RLIMIT_AS` to 256 MiB, `RLIMIT_CPU` to 5 s and `RLIMIT_CORE` to 0. The wall timeout is 5 s. stdout is capped at 1 MiB and stderr is discarded.
  - Each of these raises `InputError("static_reject")` with a generic reason: a non-zero exit, a signal, a timeout, oversize output, malformed JSON, or a worker-reported exception.
- The worker:
  - `ast.parse(text, feature_version=SCAN_FEATURE_VERSION)`;
  - findings for imports outside `INPUT_ALLOWLIST_MODULES`, with `os` allowed only as `os.path`, and `pathlib` only for the `Pure*` classes;
  - findings for `DENIED_NAMES` used as names;
  - findings for any dunder `Name` or `Attribute`;
  - a finding for `while True:`;
  - a finding when there is no top-level `def derive(ctx)`;
  - `tokenize` spans of non-ASCII characters outside `STRING`, `FSTRING_*` and `COMMENT` tokens.
- **Findings block approval.** They are shown, and `approve` refuses while any finding exists. This is the conservative reading of "static rule … caught".
- `snapshot.provider_snapshot(root: Path, name: str, *, git: str | None) -> ProviderSnapshot`. It:
  - reads the schema once with `read_schema_file`, then parses it with `parse_project_schema` (alias-bounded) and `resolve_declaration`;
  - takes `custom_declaration_set(name)`;
  - reads the script once with `read_provider_script`, then normalises and scans it;
  - runs `select_inputs`, then sizes each matched file with the reader. Per-file oversize is counted and skipped. A run total above 32 MiB is `input_cap`.
  - computes the digest.

  `ProviderSnapshot` is frozen and holds:
  - the schema hash;
  - the declaration set and its canonical JSON;
  - the script text, digest, findings and spans;
  - `matched` and its count, the sample of the first 20, `denied`, and `total_bytes`;
  - `errors: tuple[InputError, ...]`.

  `repo_snapshots(root, *, git) -> dict[str, ProviderSnapshot | InputError]` covers every declared provider.
- `snapshot.provider_state(repo_id, canon, snap, *, platform, pending: bool, registry_path, store_path) -> str` returns one of `disabled`, `unavailable`, `pending`, `awaiting_approval` or `approved`:
  - `unavailable` for an unsupported platform or an `InputError` such as no work tree;
  - `pending` when `pending` is true;
  - `disabled` when gate 1 or gate 2 is false;
  - `awaiting_approval` when gate 3 is false.

  `failing` needs run records, which arrive in E3.

**Tests**, written first:

- `test_scanner_crash_is_reject`. Each of these is a reject, never a pass:
  - a `SyntaxError`;
  - deep nesting that triggers `RecursionError` in `ast.parse`;
  - a worker killed by `RLIMIT_AS`, with the limit lowered through a test parameter;
  - a worker stalled past the timeout, with the timeout lowered and a worker-source parameter that sleeps;
  - a non-zero exit;
  - malformed JSON output.

  - a missing script is `static_reject`;
  - a provider with no matches still has a digest.
- `provider_state` table: each state from the gate results, pending, platform, and an unavailable input.
